ストレージ設計方針
  • Supabase = Primary（正）全データはここが Source of Truth
  • localStorage = Cache（副）起動高速化と offline 用途のみ
  • 起動時 + visibilitychange 時に pullFromSupabase() でマージ
  • 偏差値マスタはメモリキャッシュ _dmCache（localStorage不使用）
マルチデバイス同期の仕組み： 各デバイスで入力 → Supabase へ即座に delete/insert で全件同期。別デバイスでアプリを開いたり再フォーカスすると pullFromSupabase() が走り、Supabase を正として localStorage を上書きマージする。

04 Supabase同期設計

書き込み（Push）パターン

ローカルで CRUD 操作後、全件 delete → 全件 insert で Supabase を上書きする。楽観的ロックなし。同時書き込みは想定しない（1家庭1子ども想定）。

ユーザー操作
→
localStorage 更新
→
syncXxx() 呼び出し
→
DELETE WHERE child_name=n
→
INSERT 全件

読み込み（Pull）パターン — pullFromSupabase()

起動時と画面フォーカス復帰時に呼ばれる。Supabase を正として localStorage にマージする。

Supabase から全件取得
→
Map(id → record) でローカルと差分比較
→
新規 or 差分があれば localStorage 上書き
→
render再実行
テスト記録の pull では subjects（解き直し含む）と totalDeviation を Supabase の値で上書きする。これによりデバイス間の解き直しチェックが同期される。

sanitizeDeviationRows() — 単調性バリデーション

偏差値が高いほどスコアも高いはず、という不変条件を検証する。逆転している値は null に強制してから Supabase に保存する。

// 偏差値降順で走査。各列のスコア最大値が前行より大きければ単調性違反 → null化
for (const col of ['sansu','kokugo','rika','shakai','total2','total3','total4']) {
  let prevMin = Infinity;
  for (const row of cleaned) {         // rows は dev 降順
    const [mn, mx] = row[col] ?? [null, null];
    if (mx >= prevMin) row[col] = null; // 逆転
    else               prevMin = mn;
  }
}

偏差値逆引き — lookupDeviation(master, subject, score)

スコアから偏差値を求める。rows を上から線形探索して range に収まる最初の dev を返す（O(n)、行数は通常50行程度なので問題なし）。

Edge Function: school-deviation

四谷大塚ドットコムから志望校の C50 / A80 偏差値を取得する。学校名をパラメータに渡し、AI が該当データをスクレイピング・パースして返す。

Supabase キー管理
  • anon key（publishable）のみ使用。HTML に直書きしてよい
  • service_role / secret キーは絶対に HTML に書かない
  • Edge Function の ANTHROPIC_API_KEY は Supabase Secret に設定
セキュリティ制約： service_role キーはコード・Git 履歴・公開ファイルに絶対に含めないこと。Edge Function 内でのみ使用し、Supabase Dashboard の Secret として管理する。

Supabaseテーブル設計のコツ

  • child_name / user_id をパーティションキーとして全テーブルに持たせる
  • 複雑なネスト構造は jsonb に入れる（RLS の代わりにアプリ側でフィルタ）
  • 複合 PK は id = "キー1-キー2-キー3" の文字列連結で upsert が簡単
  • anon key は公開 OK。secret は絶対に Edge Function Secret に格納
